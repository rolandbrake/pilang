# 9.5 Semicolons and Newlines

Semicolons are optional in most places. A statement can end with either a
semicolon or a newline when the parser can clearly see that the statement is
complete.

```pilang
let x = 10
let y = 20;

println(x + y)
```

Both styles are valid.

## When Newlines End Statements

A newline can end a statement after complete expressions and declarations.

```pilang
let name = "Pilang"
println(name)

fun add(a, b) {
    return a + b
}
```

Newlines inside brackets, parentheses, braces, calls, literals, and incomplete
expressions do not end the statement.

```pilang
let values = [
    1,
    2,
    3,
]

let result = add(
    10,
    20,
)
```

## Explicit Semicolons

Use semicolons when you want multiple statements on one line.

```pilang
let x = 1; let y = 2; println(x + y)
```

Semicolons are also accepted after declarations and imports.

```pilang
import math;
let value = math.sqrt(25);
```

## Return and Newlines

`return` is sensitive to line breaks. If the expression is on the next line,
`return` returns `nil`.

```pilang
fun good() {
    return 10
}

fun returns_nil() {
    return
    10
}
```

Put the returned expression on the same line as `return`.

## Chained Expressions

If a line ends in a way that clearly continues the expression, the next line is
part of the same statement.

```pilang
let total = 1 +
    2 +
    3
```

For readability, prefer parentheses around long expressions.

```pilang
let total = (
    1 +
    2 +
    3
)
```

## Blocks

Closing braces naturally end blocks, so a semicolon is not required after a block.

```pilang
if ready {
    run()
}

while running {
    tick()
}
```

## Recommended Style

Use one statement per line and omit semicolons unless you are intentionally
placing multiple statements on a single line. This matches most examples in the
documentation.

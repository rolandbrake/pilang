# 9.4 Naming Conventions

Identifiers name variables, functions, classes, modules, fields, and parameters.

## Identifier Rules

An identifier must start with a letter or underscore.

```text
letter ::= "a".."z" | "A".."Z" | "_"
identifier ::= letter (letter | digit)*
```

Valid names:

```pilang
name
user_name
_private
value2
Point
```

Invalid names:

```pilang
2value
user-name
class
```

`class` is invalid as a variable name because it is a keyword.

## Suggested Style

Most of these are conventions, not parser requirements. The important exception
is module privacy: top-level module names that start with `_` are treated as
private by the import system.

| Kind | Convention | Example |
| --- | --- | --- |
| Variables | snake_case or simple lowercase | `total`, `user_name` |
| Variables that would shadow built-ins | add a trailing underscore | `type_`, `map_` |
| Functions | snake_case or verb phrase | `parse_json`, `make_counter` |
| Classes/prototypes | PascalCase | `Point`, `UserStore` |
| Methods | camelCase | `getItem`, `setName`, `isRunning` |
| Static-like methods | UpperCamelCase or leading uppercase | `FromList`, `CreateDefault` |
| Constants | UPPER_SNAKE_CASE | `MAX_SIZE`, `EXIT_SUCCESS` |
| Private class members | leading underscore | `_cache`, `_helper` |
| Private module names | leading underscore, enforced by imports | `_cache`, `_helper` |
| Module aliases | one short lowercase word | `math:m`, `tensor:t`, `string:s` |
| Magic methods | runtime-defined names | `format`, `compute`, `rcompute`, `getItem` |

## Snake Case by Default

Use snake_case for ordinary names with multiple words.

```pilang
let user_count = 10

fun parse_json(text) {
    return text
}
```

This keeps variables and free functions easy to scan.

## Long Names

For names with more than three parts, prefer a mixed identity/action style:
start with the subject or identity in snake_case, then use camelCase for the
specific operation.

```pilang
map_getItem
map_setItem
list_getIndex
tensor_fromNestedList
```

The first part identifies the area or data type. The second part describes the
operation. This avoids very long flat names such as
`map_get_item_from_nested_key` while still keeping related names grouped.

## Class Methods

Instance methods should usually use camelCase.

```pilang
class ListBox {
    getItem(index) {
        return this.items[index]
    }

    setItem(index, value) {
        this.items[index] = value
    }
}
```

Methods that do not use `this` are static-like helpers. Prefer an uppercase
start for those names to make them stand out from instance behavior.

```pilang
class Color {
    FromRgb(r, g, b) {
        return [r, g, b]
    }
}
```

This is a convention. Pilang does not enforce whether a method uses `this`.

## Private Names

Top-level names beginning with `_` are private to a module and are not exported.
This is part of module import behavior, not only a style preference.

```pilang
let visible = 42
let _hidden = 99
```

Other modules can import `visible`, but not `_hidden`.

Use the same leading-underscore style for private class or object members.

```pilang
class Cache {
    constructor() {
        this._items = {}
    }

    getItem(key) {
        return this._items[key]
    }
}
```

Class/object privacy is by convention. Module privacy is enforced for exports and
imports.

## Module Aliases

Module aliases should be one short lowercase name.

```pilang
import tensor:t
import math:m
import string:s

let values = t.ones(2, 2)
println(m.sqrt(25))
```

Avoid aliases with underscores or capital letters unless there is a strong
reason.

## Class and Object Names

Class declarations automatically store their class name as object metadata.

```pilang
class Point {
}

println(Object.name(Point)) // Point
```

Map-defined objects do not automatically receive a class-style name unless you
set one.

```pilang
let PointLike = {}
Object.setName(PointLike, "PointLike")
```

## Avoid Shadowing Built-ins

Pilang lets ordinary variables use many non-keyword names, but avoid shadowing
built-ins such as `len`, `map`, `type`, `print`, or module names such as `math`
unless you have a deliberate reason.

When a local value naturally has the same name as a built-in, add a trailing
underscore to the variable name:

```pilang
let type_ = typeof(value)
let map_ = {"name": "Ada"}
```

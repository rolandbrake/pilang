# 7.2 Maps as Objects

Pilang object literals are map values with object behavior. They can be simple
data maps, prototypes, or class-like objects.

## Object Literal Syntax

Use `{ key: value }` for fields.

```swift
let user = {
    name: "Ada",
    age: 36,
    active: true,
}
```

Keys can be identifiers, strings, numbers, booleans, or other supported literal
key forms.

```swift
let table = {
    "name": "Pilang",
    1: "first",
    true: "enabled",
}
```

## Method Shorthand

Use `name(params) { ... }` to define a method directly inside an object literal.

```swift
let user = {
    name: "Ada",
    greet() {
        return "Hello, " + this.name
    }
}

println(user.greet())
```

Methods defined this way receive `this`, `args`, and `kw_args`.

## Function-Valued Fields

A field can also contain an anonymous function or arrow function.

```swift
let value = 10

let Box = {
    format: () -> "Box(" + value + ")",
    equals: candidate -> is_num(candidate) && candidate == value,
}

let box = Box()
println(box.format())
```

Function-valued fields can be used as methods when read from an instance.

## Prototypes from Maps

Any object literal can act as a prototype. Calling it creates a new instance.

```swift
let Player = {
    constructor(name) {
        this.name = name
    },
    label() {
        return "Player(" + this.name + ")"
    }
}

let player = Player("Mira")
println(player.label())
```

The prototype remains available as `Player`; the constructed value is a separate
instance.

## How Map Objects Differ from Classes

Map-defined objects and classes both create prototype objects, but map-defined
objects are more direct and more dynamic.

```swift
let Player = {
    kind: "player",
    constructor(name) {
        this.name = name
    }
}
```

This is different from a class in a few practical ways:

- map fields use `:` while class fields use `=`
- map prototypes are not automatically locked
- map prototypes allow string-key bracket access by default
- map prototypes do not automatically receive an intrinsic name from syntax
- inheritance is explicit with `Object.extends(parent, child)` or
  `child.extends(parent)`
- object literals can also be used as plain data maps without ever acting like a
  class

```swift
let Animal = {
    kind: "animal"
}

let Dog = Object.extends(Animal, {
    constructor(name) {
        this.name = name
        this.kind = "dog"
    }
})
```

The equivalent class form is more declarative:

```swift
class Animal {
    kind = "animal"
}

class Dog : Animal {
    constructor(name) {
        this.name = name
        this.kind = "dog"
    }
}
```

Choose map-defined objects for flexible prototypes, object literals, configuration
objects, ad-hoc behavior, and cases where you want to compose objects manually.
Choose classes when the value represents a named type with a stable shape.

## Prototype Fields vs Instance Fields

Fields on the prototype are shared defaults. Assigning to an instance writes to
that instance.

```swift
let Point = {
    c: 10,
    constructor(x, y) {
        this.x = x
        this.y = y
    }
}

let a = Point(1, 2)
let b = Point(3, 4)

a.c = a.c + 1

println(a.c)     // 11
println(b.c)     // 10
println(Point.c) // 10
```

## Bracket Access

Object literals allow bracket member access by default.

```swift
let MapLike = {
    value: 41,
    inc() {
        return 42
    }
}

println(MapLike["value"])
println(MapLike["inc"]())
```

Use `bracketAccess(false)` to disable string-key bracket access on an object, and
`bracketAccess(true)` to enable it again.

```swift
MapLike.bracketAccess(false)
println(MapLike.value)

MapLike.bracketAccess(true)
println(MapLike["value"])
```

Non-string keys can be handled with `getItem` and `setItem`. See
[Magic Methods](7.8-magic-methods.md).

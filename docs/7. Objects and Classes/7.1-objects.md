# 7.1 Objects

An object is a map-like value with fields, methods, and an optional prototype
parent. Objects are created from object literals, class declarations, or by
calling an object that acts as a prototype.

```swift
let user = {
    name: "Ada",
    age: 36,
    greet() {
        return "Hello, " + this.name
    }
}

println(user.name)
println(user.greet())
```

## Fields

Fields store values by name.

```swift
let point = {
    x: 2,
    y: 4,
}

println(point.x)      // 2
println(point["y"])   // 4
```

Dot access is the normal style for string-like property names. Bracket access is
useful when the key is computed.

```swift
let key = "x"
println(point[key])
```

## Methods

A method is a function stored on an object. When called through the object, it is
bound to `this`.

```swift
let counter = {
    value: 0,
    inc() {
        this.value = this.value + 1
        return this.value
    }
}

println(counter.inc()) // 1
println(counter.inc()) // 2
```

## Prototypes and Instances

Object literals can be used as prototypes. Calling a prototype creates an
instance. If the prototype has a `constructor` method, Pilang runs it for the new
instance.

```swift
let Point = {
    constructor(x, y) {
        this.x = x
        this.y = y
    },
    label() {
        return "(" + this.x + ", " + this.y + ")"
    }
}

let p = Point(3, 4)
println(p.label()) // (3, 4)
```

The instance stores its own fields, while methods are usually found through the
prototype chain.

## Classes vs Map Objects

Classes and map-defined objects share the same underlying object model: both are
prototype maps that can be called to create instances. The main differences are
syntax and defaults.

| Feature | Map-defined object | Class |
| --- | --- | --- |
| Definition form | `let Type = { key: value }` | `class Type { key = value }` |
| Field separator | `:` | `=` |
| Inheritance | `Object.extends(parent, child)` or `child.extends(parent)` | `class Child : Parent` |
| Name | not automatically named unless assigned/renamed | class name is stored automatically |
| Locking | flexible by default | prototype is locked after declaration |
| String bracket access | enabled by default | disabled by default |
| Best use | dynamic prototypes, plain records, quick object values | named types with a stable shape |

These two definitions create similar callable prototypes:

```swift
let MapPoint = {
    constructor(x, y) {
        this.x = x
        this.y = y
    }
}

class ClassPoint {
    constructor(x, y) {
        this.x = x
        this.y = y
    }
}

let a = MapPoint(1, 2)
let b = ClassPoint(1, 2)
```

Use a map-defined object when you want a lightweight object or a prototype you
can freely build up. Use a class when you want a named, stricter prototype with
clear inheritance syntax.

## `this`

Inside a method or constructor, `this` is the current receiver.

```swift
let Box = {
    constructor(value) {
        this.value = value
    },
    get() {
        return this.value
    }
}

let box = Box(10)
println(box.get()) // 10
```

## Callable Objects

An instance can be called like a function if it defines a `call` method.

```swift
let Counter = {
    count: 0,
    call() {
        this.count = this.count + 1
        return this.count
    }
}

let counter = Counter()
println(counter()) // 1
println(counter()) // 2
```

Arguments are forwarded to `call`.

```swift
let Adder = {
    base: 5,
    call(x, y) {
        return x + y + this.base
    }
}

let add = Adder()
println(add(1, 2)) // 8
```

## Object Helpers

All object-like maps inherit helper methods from `Object`, including `get`,
`set`, `has`, `delete`, `keys`, `values`, `clone`, `type`, `name`, `equals`, and
`compare`.

```swift
println(user.has("name"))
println(user.get("age"))

user.set("active", true)
println(user.keys())
```

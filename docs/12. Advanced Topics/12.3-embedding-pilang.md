# 12.3 Embedding Pilang

Embedding means running Pilang from another host program instead of only using the command-line executable.

The runtime is written in C, so a host application can use the same pipeline as the native executable:

```text
source text
  -> init scanner
  -> scan tokens
  -> initialize compiler
  -> initialize parser
  -> parse and compile
  -> initialize VM
  -> run VM
  -> free parser, VM, and compiler
```

## Native embedding shape

The native runner follows this structure:

```c
init_scanner((char *)source);
token_t *tokens = scan();

compiler_t *comp = init_compiler();
parser_t *parser = init_parser(comp, tokens, MODE_FILE);
parse(parser);

vm_t *vm = init_vm(comp, entry_name, true);

while (vm->running)
    run(vm);

free_parser(parser);
free_vm(vm);
free_compiler(comp);
```

This is the basic pattern a host program should follow.

## Choosing parser mode

The parser mode describes how source should be treated.

- `MODE_FILE` is used for normal files.
- `MODE_REPL` is used for interactive input.

Use file mode when running a full script or module. Use REPL mode when accepting one interactive input at a time.

## Entry names

The VM receives an entry name. For files, this is normally the file path. For generated or embedded source, use a descriptive name such as:

```text
<embedded>
<browser>
<plugin>
<repl>
```

Good entry names make parser errors, runtime errors, and debug output easier to understand.

## Registering native functions

Built-in functions are C functions with this shape:

```c
Value native_name(vm_t *vm, int argc, Value *argv)
```

They receive:

- the active VM
- the number of arguments
- an array of Pilang `Value` arguments

They return a Pilang `Value`.

Example shape:

```c
Value host_log(vm_t *vm, int argc, Value *argv)
{
    for (int i = 0; i < argc; i++)
    {
        char *text = pi_displayString(vm, argv[i]);
        fputs(text, stdout);
        free(text);
    }

    return NEW_NIL();
}
```

Native functions should validate arguments and report errors with `vm_error` or `vm_errorf`.

## Native modules

Built-in modules group native functions and constants under one imported name.

```pilang
import host:h

h.log("hello from Pilang")
```

Internally, a built-in module contains a module name, function table, constant table, and counts for both.

Use a module when your host exposes several related functions.

## Error handling

The runtime has parser errors and VM runtime errors. Host programs should install or use the runtime's error handling path so errors are reported in the host environment.

For command-line programs, errors can be printed to standard error. For browser embedding, errors are forwarded to JavaScript callbacks.

## Browser embedding

The Emscripten build exposes browser-facing functions such as:

- setting source
- executing source
- disassembling source
- stopping execution
- pausing execution
- resuming execution

This allows a web editor or playground to run Pilang code without launching a native process.

## Resource cleanup

Always release runtime resources after execution:

```c
free_parser(parser);
free_vm(vm);
free_compiler(comp);
```

If the host repeatedly runs short scripts, cleanup prevents old globals, objects, modules, and bytecode metadata from leaking into the next run.

## Embedding checklist

- Initialize the scanner with source text.
- Scan tokens.
- Create a compiler.
- Set a useful source or entry name.
- Create a parser with the correct mode.
- Parse and compile before creating the VM.
- Run while `vm->running`.
- Report errors through the host.
- Free parser, VM, and compiler when done.

# 6.4 Arguments

Arguments are the values passed to a function call. Pilang supports positional
arguments, default parameters, named arguments, and spread arguments.

## Positional Arguments

Positional arguments are matched to parameters by order.

```pilang
fun subtract(a, b) {
    return a - b
}

println(subtract(10, 3)) // 7
```

## Default Arguments

Parameters can define default values.

```pilang
fun greet(name, punctuation = "!") {
    println("Hello, " + name + punctuation)
}

greet("Mira")      // Hello, Mira!
greet("Mira", ".") // Hello, Mira.
```

If an argument is omitted, its default value is used. If no default is provided,
the missing value is `nil`.

```pilang
fun show(a, b) {
    println(a)
    println(b)
}

show(1) // b is nil
```

## Named Arguments

Calls can pass named arguments with `name = value`.

```pilang
fun hanoi(ndisks, startPeg = 1, endPeg = 3) {
    println("move " + ndisks + " from " + startPeg + " to " + endPeg)
}

hanoi(4, endPeg = 2)
```

Named arguments are collected into the call's `kw_args` map and matched to
declared parameters by name. This makes optional parameters easier to read at the
call site.

In the example above:

- `ndisks` receives `4` from the positional argument
- `startPeg` is omitted, so it uses the default `1`
- `endPeg` receives `2` from the named argument

Once a named argument appears, later arguments in the same call must also be
named.

```pilang
fun format_name(first, last, title = "") {
    return title + first + " " + last
}

format_name("Ada", "Lovelace", title = "Countess ")
```

This is invalid because a positional argument appears after a named one:

```pilang
// Invalid
format_name(first = "Ada", "Lovelace")
```

If a parameter already received a positional argument, passing it again by name is
an error.

```pilang
// Invalid: last receives both "Lovelace" and "Byron"
format_name("Ada", "Lovelace", last = "Byron")
```

Named arguments that do not match declared parameters remain available in
`kw_args`. This lets a function accept option-like values even when they are not
part of the declared arity.

```pilang
fun configure(name) {
    println(name)
    println(kw_args)
}

configure("server", retries = 3, verbose = true)
```

## Spread Arguments

Use `...` inside a call to expand a list of positional arguments.

```pilang
fun add(a, b, c) {
    return a + b + c
}

let values = [1, 2, 3]
println(add(...values)) // 6
```

Spread positional arguments must come before named arguments.

```pilang
let base = [4]

hanoi(...base, endPeg = 2)
```

The spread value must be a list of values to pass.

## The `args` and `kw_args` Locals

Every function receives two helper locals:

- `args` contains the positional arguments passed to the call, including extra
  positional arguments that were not bound to declared parameters.
- `kw_args` contains the named arguments passed to the call.

```pilang
fun inspect(a, b = nil) {
    println(args)
    println(kw_args)
}

inspect(10, mode = "fast")
```

These are useful for debugging, forwarding arguments, and writing flexible
helpers.

## Arity and Argument Counts

A function's declared arity is the number of parameters in its declaration.
Functions can declare up to 32 parameters.

```pilang
fun example(a, b, c = 0) {
    println(args)
    println(kw_args)
}
```

`example` has an arity of `3`.

Calls do not have to provide exactly that many positional arguments:

- missing parameters use defaults or `nil`
- extra positional arguments are kept in `args`
- named arguments are kept in `kw_args`
- matching named arguments also fill parameters with the same names

Calls can pass multiple positional arguments and up to 256 named arguments, but
the practical call shape should stay readable. Prefer maps or objects when a
function needs many options.

## Functions as Arguments

Because functions are values, they can be passed like any other argument.

```pilang
fun apply(value, operation) {
    return operation(value)
}

println(apply(5, n -> n * n)) // 25
```

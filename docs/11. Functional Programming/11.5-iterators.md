# 11.5 Iterators

Iterators let code process values one at a time instead of manually managing indexes everywhere. In Pilang, iteration appears in three common forms:

- `for ... in` loops over iterable values.
- Iterator objects can expose `iterator()` and `next()` behavior.
- The `func` module can create iterator-style functions such as `func.iterate`.

## for in

The most common iteration syntax is `for ... in`.

```swift
numbers = [1, 2, 3]

for n in numbers {
    print(n)
}
```

This works naturally with iterable values such as lists, tuples, sets, strings, maps, ranges, and custom iterable objects.

## Iterating strings

Strings can be processed one character at a time.

```swift
for ch in "pilang" {
    print(ch)
}
```

String indexing wraps when the index is larger than the string length, but iteration walks the string in order.

## Iterating maps

Maps iterate over their keys.

```swift
user = {
    "name": "Mira",
    "role": "admin"
}

for key in user {
    print(key + ": " + user[key])
}
```

Use the key to access the value.

## Iterating sets

Sets contain unique values. Iteration visits the values in the set.

```swift
tags = {"docs", "lang", "docs"}

for tag in tags {
    print(tag)
}
```

Do not depend on set ordering unless the implementation of the specific set operation documents an order.

## Iterator protocol style

Objects can participate in iteration by exposing iterator-style behavior. A common pattern is:

- `iterator()` returns an iterator object.
- `next()` returns the next value.
- `next()` returns `nil` when there are no more values.

Example shape:

```swift
counter = {
    "value": 0,
    "limit": 3,

    "iterator": fun (this) {
        return this
    },

    "next": fun (this) {
        if this["value"] >= this["limit"] {
            return nil
        }

        current = this["value"]
        this["value"] += 1
        return current
    }
}

for n in counter {
    print(n)
}
```

This pattern is useful for values that are computed lazily.

## func.iterate

`func.iterate(seed, fun)` creates a function that returns a sequence of values. The first call returns the seed. Each later call returns the current value and advances the sequence by applying the function.

```swift
import func:f

next_power = f.iterate(1, n -> n * 2)

print(next_power()) // 1
print(next_power()) // 2
print(next_power()) // 4
print(next_power()) // 8
```

This is useful when you want lazy repeated _transformation without building a list first.

## Taking values from an iterator function

You can combine `func.iterate` with normal loops.

```swift
import func:f

next_value = f.iterate(10, n -> n + 10)
values = []

for i in range(0, 5) {
    values = values + next_value()
}

print(values) // [10, 20, 30, 40, 50]
```

## find

`find` is a functional search helper. It accepts a collection and a predicate.

```swift
index = find(collection, predicate)
```

For lists, it returns the index of the first matching item, or `-1` if no item matches.

```swift
numbers = [3, 7, 10, 12]

index = find(numbers, n -> n > 9)

print(index) // 2
```

For strings, the predicate receives each character as a string.

```swift
index = find("pilang", ch -> ch == "a")

print(index) // 3
```

## Checking iterability

The `col` module provides helpers for collection-like values, including checking whether a value is iterable.

```swift
import col:c

print(c.is_iterable([1, 2, 3])) // true
print(c.is_iterable(42)) // false
```

## Iterators and mutation

Be careful when mutating a collection while iterating over it.

```swift
numbers = [1, 2, 3]

for n in numbers {
    numbers = numbers + (n * 10)
}
```

Changing the iterable during iteration can make code harder to reason about. Prefer creating a new list with `map`, `filter`, or `reduce` when the goal is _transformation.

## Notes

- Use `for ... in` for normal collection traversal.
- Use `map`, `filter`, and `reduce` when you want expression-style _transformations.
- Use `func.iterate` for lazy repeated values.
- Use `find` when you need the first matching index.
- Custom iterators should clearly define how iteration ends.

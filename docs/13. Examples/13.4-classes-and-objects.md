# 13.4 Classes and Objects

Pilang supports both map-defined objects and class declarations. Use maps when you want flexible object literals. Use classes when you want named prototypes, constructors, methods, and inheritance.

## A class

```pilang
class Point {
    constructor(x = 0, y = 0) {
        this.x = x
        this.y = y
    }

    move(dx, dy) {
        this.x += dx
        this.y += dy
        return this
    }

    length() {
        return (this.x ** 2 + this.y ** 2) ** 0.5
    }

    format() {
        return "Point(" + this.x + ", " + this.y + ")"
    }
}

p = Point(3, 4)

println(p.format()) // Point(3, 4)
println(p.length()) // 5

p.move(10, -2)
println(p.format()) // Point(13, 2)
```

## Inheritance

```pilang
class Animal {
    constructor(name) {
        this.name = name
    }

    speak() {
        return this.name + " makes a sound"
    }
}

class Dog : Animal {
    constructor(name, breed) {
        super(name)
        this.breed = breed
    }

    speak() {
        return this.name + " barks"
    }

    describe() {
        return this.name + " is a " + this.breed
    }
}

dog = Dog("Luna", "shepherd")

println(dog.speak())
println(dog.describe())
```

## A map-defined object

```pilang
counter = {
    "value": 0,

    "inc": fn (this) {
        this["value"] += 1
        return this["value"]
    },

    "reset": fn (this) {
        this["value"] = 0
    }
}

println(counter["inc"](counter)) // 1
println(counter["inc"](counter)) // 2
counter["reset"](counter)
println(counter["value"]) // 0
```

Map-defined objects are flexible. You can add fields freely:

```pilang
counter["label"] = "main counter"
println(counter["label"])
```

## Class-style object construction

Object literals can also define constructors.

```pilang
let User = {
    constructor(name, role = "user") {
        this.name = name
        this.role = role
    },

    describe() {
        return this.name + " (" + this.role + ")"
    }
}

admin = User("Mira", "admin")
println(admin.describe())
```

## When to use each form

Use classes when:

- the object has a clear type name
- you want constructor syntax
- you want inheritance
- you want stricter prototype behavior
- several instances should share methods

Use map objects when:

- you need a small record
- fields are dynamic
- the object is mostly data
- you want bracket-key access

## What this example uses

- classes
- constructors
- methods
- `this`
- inheritance
- `super`
- map-defined objects

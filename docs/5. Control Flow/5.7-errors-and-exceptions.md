# 5.7 Errors and Exceptions

Pilang currently reports errors through lexer errors, parser errors, runtime VM errors, and assertions. The current parser does not define `try`, `catch`, `throw`, or exception-handling syntax.

## Lexer Errors

Lexer errors happen while source text is being tokenized.

Common examples:

- unterminated strings
- unclosed block comments
- invalid numeric literals
- leading zeros in decimal integer literals

```swift
// Invalid: decimal leading zero
let n = 012;
```

## Parser Errors

Parser errors happen when the token stream does not match Pilang syntax.

Common examples:

- `break` or `continue` outside a loop
- invalid assignment targets
- missing closing braces or parentheses
- invalid function parameter lists
- unreachable code after `return`, `break`, or `continue` in a block
- returning a value from a constructor

```swift
// Invalid
break;
```

```swift
// Invalid
1 + 2 = value;
```

## Runtime Errors

Runtime errors happen while bytecode is executing.

Common examples:

- calling a non-function value
- using an operator with unsupported operand types
- indexing a value that does not support indexing
- using a non-iterable in a `for` loop
- setting a string item, because strings are immutable
- invalid tensor indexing or shape operations
- invalid spread values

```swift
let n = 1;
n[0]; // runtime error: numbers are not indexable
```

## Assertions

Pilang provides an `assert` built-in. Use it to validate assumptions while testing.

```swift
assert(1 + 1 == 2, "math still works");
```

If the assertion fails, the runtime reports an error.

```swift
assert(false, "this fails");
```

## Error Recovery

There is no user-level exception recovery syntax yet. A parser or runtime error stops the current program execution.

Structure code defensively when a value may be invalid:

```swift
if value != nil {
    println(value);
}
```

Use conditionals, type checks, and validation before operations that may fail.

```swift
if typeof value == "list" {
    println(value[0]);
}
```

## Error Messages

Errors are reported with line and column information when available. Runtime errors may include the module or function context to help locate the failure.

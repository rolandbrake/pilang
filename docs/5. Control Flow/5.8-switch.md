# 5.8 Switch

`switch` checks cases in order and runs the first matching body. It supports
both subject-based matching and condition-only switches. The `_` case is the
default path.

```swift
switch exp {
    exp == 1:
        println(1)
    exp > 2 && exp < 4:
        println(2)
    exp in 1..10:
        println(3)
    exp in [1, 2, 3]:
        println(4)
    _:
        println(5)
}
```

Literal cases are implicitly compared with the switch subject:

```swift
switch exp {
    1: println("one")
    2: println("two")
    3: println("three")
    _: println("other")
}
```

Explicit conditions are also supported. They are evaluated as written.

```swift
switch exp {
    exp in 1..10:
        println("inside the range")
    1..10:
        println("the range object itself is truthy")
}
```

When no subject is provided, `switch` becomes a condition switch. Each case
must be a condition, and the first truthy condition is selected:

```swift
switch {
    score >= 90: println("A")
    score >= 80: println("B")
    passed: println("already passed")
    _: println("needs review")
}
```

Literal shorthand such as `1:` is intended for subject-based switches. Use an
explicit condition in a condition switch, such as `value == 1:`.

Use a single statement after `:` for short cases. Use braces when a case body
has more than one statement.

```swift
switch score {
    score >= 90: println("A")
    score >= 80: {
        println("B")
        passed = true
    }
    _: println("needs review")
}
```

There is no fallthrough. Once a case body runs, the switch statement ends.

Literal cases and cases with the simple form `name == literal`, where `name`
is the switch expression, use a specialized comparison instruction. Condition
switches and more complex cases retain ordered evaluation semantics.

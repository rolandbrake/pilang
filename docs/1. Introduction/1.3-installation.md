# 1.3 Installation

This repository currently includes a Windows executable named `pilang.exe` at the project root. If you already have the repository, you can run Pilang scripts from that directory without a separate installer.

## Requirements

For the native Windows build in this repository:

- `pilang.exe`
- SDL runtime DLLs beside the executable, including `SDL2.dll`, `SDL2_image.dll`, `SDL2_mixer.dll`, and `SDL2_ttf.dll`

For rebuilding from source on Windows, the project uses:

- MinGW GCC at `C:\MinGW64\bin\gcc.exe`
- SDL2, SDL2_image, SDL2_mixer, and SDL2_ttf development libraries
- `mingw32-make` for the Makefile workflow

## Using The Included Executable

Open a terminal in the repository root and run:

```powershell
.\pilang.exe help
```

You should see the Pilang command help.

## Building From Source

The repository includes a root `Makefile` that mirrors the native and browser build settings used by the VS Code tasks. On Windows with MinGW installed, run Makefile targets with `mingw32-make` from the repository root.

Build the optimized native executable:

```powershell
mingw32-make release
```

This produces `pilang.exe` in the repository root.

Build a debug executable:

```powershell
mingw32-make debug
```

The debug target enables `DEBUG_BUILD` and keeps debug symbols.

Build the browser/WebAssembly version:

```powershell
mingw32-make web
```

This uses Emscripten's `emcc` and writes the browser output files such as `pilang.html`, `pilang.js`, and `pilang.wasm`.

Other useful targets:

- `mingw32-make`: same as `mingw32-make release`.
- `mingw32-make run`: build the release executable and run it.
- `mingw32-make test`: build the release executable and run `python tools/run_tests.py`.
- `mingw32-make clean`: remove generated build outputs.

You can override the compiler or output name from the command line:

```powershell
mingw32-make release CC=C:\MinGW64\bin\gcc.exe TARGET=pi-dev.exe
```

The repository also includes VS Code build tasks:

- `build-debug`
- `build-release`
- `build-emscripten`

The Makefile is the recommended command-line build path. The VS Code tasks remain useful if you prefer building from inside the editor.

## Example

```powershell
.\pilang.exe --version
```

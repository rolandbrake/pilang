# 1.3 Installation

Most people should use a Pilang release rather than build from source. A release
contains a ready-to-run `pilang` executable and does not require a compiler or
SDL development libraries.

## Build from source

Source builds use the prebuilt SDL packages supplied by the operating system.
They do not compile SDL from source.

### Windows

Install MSYS2, then open PowerShell in the repository and run:

```powershell
.\tools\setup.ps1 -InstallMSYS2
```

Open the **MSYS2 UCRT64** terminal, change to the repository, and build:

```sh
make release
./bin/pilang.exe help
```

### Linux and macOS

From the repository root, install the build dependencies for your package
manager and build:

```sh
sh tools/setup.sh
make release
./bin/pilang help
```

`tools/setup.sh` supports apt, dnf, pacman, and Homebrew. It installs a C
compiler, `make`, `pkg-config`, and the SDL2 development packages Pilang uses.

## Other build targets

```sh
make debug    # debug executable in bin/
make test     # build and run the test suite
make web      # browser/WebAssembly build; requires Emscripten
make clean    # remove generated build outputs
```

## Static Windows dependencies

`make static-deps` remains available for maintainers producing a fully static
Windows build. It downloads and compiles SDL and is intentionally not part of
the normal development setup.

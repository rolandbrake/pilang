# 8.1 Importing Modules

Use `import` to load a module and make its exports available.

```pilang
import math

println(math.sqrt(25))
```

Module lookup prefers source files before built-ins. Pilang first looks for a
user-defined module near the importing file, then checks the shared `libs`
directory, and finally falls back to native built-in modules. See
[Module Paths](8.3-module-paths.md) for the full resolution order.

## Plain Imports

A plain import binds the module to its final path segment.

```pilang
import tensor

let values = tensor.ones(2, 3)
println(values)
```

For nested module paths, the final segment becomes the local name.

```pilang
import tests.module.private_module

println(private_module.visible)
```

## Module Aliases

Use `:` after the module path to bind the module to another name.

```pilang
import tensor:ten

let values = ten.zeros(2, 2)
```

Aliases are useful for long module paths or common modules used repeatedly.

## Selected Imports

Use `{ ... }` to import selected exports from a module.

```pilang
import math.{floor, ceil}

println(floor(3.9))
println(ceil(3.1))
```

Selected imports bind the named exports directly in the current scope.

## Selected Imports with Aliases

Use `name:alias` inside the selector list.

```pilang
import math.{floor:math_floor, ceil:math_ceil}

println(math_floor(3.9))
println(math_ceil(3.1))
```

You can mix aliased and non-aliased imports.

```pilang
import tensor.{eye:identity, size}

let matrix = identity(3, 3)
println(size(matrix))
```

## Single Export Alias

Use a dotted export path followed by `:alias` to import one export directly.

```pilang
import tensor.ones:make_ones

let matrix = make_ones(2, 2)
```

## Wildcard Imports

Use `.*` to import every public export into the current module/global scope.

```pilang
import math.*

println(sqrt(25))
println(PI)
```

Wildcard imports are convenient for quick scripts, but selected imports are
clearer in larger files because they show which names are used.

## Private Names

Exports whose names start with `_` are private. They are not imported by
wildcard imports, and direct access from outside the module is rejected.

```pilang
// Invalid if _hidden belongs to an imported module
import some.module.{_hidden}
```

## Import Statements and Semicolons

Import statements may end with a semicolon, but it is not required.

```pilang
import math;
import tensor
```

## Import Cache

Modules are loaded and cached by resolved path. Importing the same file again
returns the cached module object instead of re-running the file.

# 10.2 Object Lifetime

An object's lifetime is the time between allocation and garbage collection.

Objects are allocated when you create heap values such as strings, lists, maps,
sets, tuples, functions, tensors, ranges, modules, and instances.

```swift
let text = "hello"
let values = [1, 2, 3]
let user = { name: "Ada" }
```

These values live while reachable.

## Local Lifetime

Objects created in a function are local unless returned, captured, stored in a
global/module variable, or stored inside another live object.

```swift
fun temporary() {
    let values = [1, 2, 3]
    println(values)
}

temporary()
```

After `temporary` returns, the list can be collected because no live value refers
to it.

## Returned Objects

Returning an object keeps it alive through the caller's reference.

```swift
fun make_list() {
    return [1, 2, 3]
}

let values = make_list()
```

The list remains alive while `values` or another live reference points to it.

## Global and Module Lifetime

Top-level variables live in the module's global scope. A global reference keeps
an object alive as long as the module remains loaded.

```swift
let cache = {}

fun remember(key, value) {
    cache[key] = value
}
```

Imported modules are cached, so their globals can live for the rest of the
program.

To release a module-level reference, overwrite it with another value such as
`nil` or an empty collection.

```swift
cache = nil
```

## Object Graphs

Objects keep other objects alive through their fields and elements.

```swift
let profile = {
    name: "Ada",
    tags: ["math", "code"],
}
```

As long as `profile` is live, the `tags` list and the strings inside it are also
live.

## Instances and Prototypes

Class instances reference their prototype chain. Prototypes are usually stored in
module/global variables, so they normally live as long as the module.

```swift
class Point {
    constructor(x, y) {
        this.x = x
        this.y = y
    }
}

let p = Point(1, 2)
```

`p` keeps its instance fields alive. The class value `Point` keeps the prototype
alive.

## Iteration Lifetime

Active loops and iterators keep the current iterable reachable while iteration is
in progress.

```swift
for item in [1, 2, 3] {
    println(item)
}
```

The temporary list stays alive until the loop no longer needs it.

## External Resources

Some objects represent external resources, such as files, drawing contexts, or
processes. Their memory is managed automatically, but the external resource
should still be closed or stopped explicitly when the API provides a function.

```swift
import fs

let f = fs.open("data.txt", "r")
let text = fs.read(f)
fs.close(f)
```

Do not rely on garbage collection as a substitute for `fs.close`, `draw.close`,
or similar cleanup functions.

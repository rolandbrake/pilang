# 10.1 Garbage Collection

Pilang uses automatic garbage collection for heap-allocated values.

Managed values include:

- strings
- lists
- tuples
- sets
- maps and object instances
- functions and closures
- modules
- tensors
- ranges and slices
- drawing and plotting objects where supported

Primitive values such as numbers, booleans, and `nil` are stored directly and do
not need collection.

## Mark and Sweep

The collector is mark-and-sweep:

1. Start from root values that are known to be reachable.
2. Mark every object reachable from those roots.
3. Sweep through allocated objects and free anything unmarked.
4. Clear marks on live objects for the next cycle.

You normally do not notice this process while writing Pilang code.

## GC Roots

An object is kept alive if it is reachable from a root.

Important roots include:

- values on the VM stack
- active function call frames
- the current function
- global/module variables
- loaded modules and their exports
- constants used by compiled code
- active iterators
- open closure upvalues
- objects referenced by other live objects

```swift
let values = [1, 2, 3]
let user = {
    name: "Ada",
    scores: values,
}
```

Here, `values` is reachable directly through the global `values` name and also
through `user.scores`.

## When Collection Happens

The runtime tracks object allocations and runs garbage collection after an
allocation threshold is reached. The threshold adapts based on how many objects
remain live after a collection.

You can also request collection manually through the `sys` module:

```swift
import sys

sys.gc()
```

Manual GC is usually only useful for tests, debugging, or long-running scripts
that just released a large amount of temporary data.

## Reachability, Not Scope Alone

Leaving a scope makes local variables unavailable, but objects they referenced
are only collectible if no other live value still references them.

```swift
fun make_user() {
    let user = { name: "Ada" }
    return user
}

let saved = make_user()
```

The local variable `user` is gone after `make_user` returns, but the object is
still alive because `saved` references it.

## Cycles

Because the collector traces reachability, reference cycles can be collected when
the whole cycle becomes unreachable.

```swift
let a = {}
let b = {}

a.other = b
b.other = a

a = nil
b = nil
```

After both names stop referencing the cycle, the objects may be collected.

## What GC Does Not Do

Garbage collection does not close files, stop OS processes, close windows, or
undo external side effects. Close or clean up external resources explicitly when
the module provides a function for it.

```swift
import fs

let f = fs.open("notes.txt", "w")
fs.write(f, "hello")
fs.close(f)
```

# 4.6 Operator Overloading

Pilang object instances can customize operator behavior with methods. These methods are looked up on the object or its prototype chain and are bound to `this` before they are called.

## Hook Summary

| Method | Used by |
| --- | --- |
| `compute(op, other)` | binary arithmetic, bitwise, shift, exponent, and dot-product operators |
| `rcompute(op, other)` | reflected binary arithmetic when the object is the right operand |
| `compute(op)` | selected unary operators |
| `equals(other)` | `==`, `!=` |
| `compare(other)` | `<`, `>`, `<=`, `>=` |
| `format()` | primitive conversion for string/numeric operations |
| `getItem(index)` | custom bracket/member read for non-string keys |
| `setItem(index, value)` | custom bracket/member write for non-string keys |
| `call(...)` | calling an object instance like a function |

## `compute`

For object instances, Pilang tries `compute` for many arithmetic-style operators when the object is the left operand.

```pilang
class Vector {
    constructor(x = 0, y = 0) {
        this.x = x;
        this.y = y;
    }

    compute(op, other) {
        if op == 0 {
            return Vector(this.x + other.x, this.y + other.y);
        }

        if op == 2 {
            return Vector(this.x * other, this.y * other);
        }

        return nil;
    }
}
```

Binary `compute(op, other)` receives the operator code and the right operand.

## `rcompute`

`rcompute(op, other)` customizes the same binary operators when the object is the right operand. It receives the operator code and the left operand, so `5 - value` calls `value.rcompute(OP_SUB, 5)`.

```pilang
import lang

class Box {
    constructor(value) {
        this.value = value
    }

    compute(op, other) {
        if op == lang.OP_SUB {
            return this.value - other
        }
        error("unsupported operator")
    }

    rcompute(op, other) {
        if op == lang.OP_SUB {
            return other - this.value
        }
        error("unsupported reflected operator")
    }
}

let box = Box(10)
println(box - 3)  // 7
println(20 - box) // 10
```

Pilang checks primitive numeric operations first, so expressions such as `1 + 1` use the direct numeric fast path and do not perform object method lookup. Reflected dispatch is only considered after those fast paths and only for object instances whose prototype chain declares `rcompute`.

| Code | Operator |
| --- | --- |
| `0` | `+` |
| `1` | `-` |
| `2` | `*` |
| `3` | `/` |
| `4` | `%` |
| `7` | `**` |
| `8` | `&` |
| `9` | `|` |
| `10` | `^` |
| `11` | `<<` |
| `12` | `>>` |
| `13` | `>>>` |
| `14` | `@` / `*.` |

Unary `compute(op)` receives `100 + unary_code`.

| Code | Operator |
| --- | --- |
| `100` | unary `+` |
| `101` | unary `-` |
| `103` | unary `~` |

These operators are not handled through `compute`: `&&`, `||`, `!`, `#`, `typeof`, and `is`.

## `equals`

`equals(other)` customizes `==` and `!=`.

```pilang
class Id {
    constructor(value = nil) {
        this.value = value;
    }

    equals(other) {
        return other.value == this.value;
    }
}
```

If the left side has `equals`, Pilang uses it. If not, Pilang also tries the right side's `equals`.

## `compare`

`compare(other)` customizes ordered comparisons: `<`, `>`, `<=`, and `>=`.

```pilang
class Box {
    constructor(size = 0) {
        this.size = size;
    }

    compare(other) {
        return this.size - other.size;
    }
}
```

`compare(other)` must return a number:

- negative if `this` is less than `other`
- zero if they are equal
- positive if `this` is greater than `other`

If the left side does not provide `compare`, Pilang may try the right side's `compare` and flip the sign.

## `format`

`format()` is used when Pilang tries to coerce an object instance to a primitive value for string or numeric operations.

```pilang
class Label {
    constructor(text = "") {
        this.text = text;
    }

    format() {
        return this.text;
    }
}

let label = Label("score");
println(label + ": " + 10);
```

If `format()` returns a string or another primitive value, that value can participate in the operation. If it returns another object, Pilang keeps the original object.

## `getItem`

`getItem(index)` customizes bracket/member reads for object instances when the key is not a string.

```pilang
class Bag {
    constructor() {
        this.values = [10, 20, 30];
    }

    getItem(index) {
        return this.values[index];
    }
}

let bag = Bag();
println(bag[1]); // 20
```

String keys use normal map/object lookup, so `obj["name"]` and `obj.name` read fields directly instead of calling `getItem("name")`.

## `setItem`

`setItem(index, value)` customizes bracket/member writes for object instances when the key is not a string.

```pilang
class Bag {
    constructor() {
        this.values = [0, 0, 0];
    }

    setItem(index, value) {
        this.values[index] = value;
    }

    getItem(index) {
        return this.values[index];
    }
}

let bag = Bag();
bag[1] = 42;
println(bag[1]); // 42
```

String-key writes use normal map/object field assignment.

```pilang
bag.name = "primary";
bag["name"] = "primary";
```

## `call`

`call(...)` makes an object instance callable.

```pilang
class Multiplier {
    constructor(factor = 1) {
        this.factor = factor;
    }

    call(value = 0) {
        return value * this.factor;
    }
}

let double = Multiplier(2);
println(double(21)); // 42
```

Named arguments and spread calls are passed through to `call` just like normal function calls.

## Built-in Object Methods

All object-like values inherit methods from `Object`. These are not all operator overload hooks, but they are commonly used alongside overloaded behavior.

| Method | Purpose |
| --- | --- |
| `format()` | string/primitive formatting hook |
| `hash()` | identity-style hash value |
| `clone()` | clone a map/object |
| `extends(parent)` | set a prototype parent |
| `equals(other)` | default equality helper |
| `ident(other)` | object identity comparison |
| `compare(other)` | default comparison helper |
| `type()` | runtime type name |
| `name()` | intrinsic object/prototype name |
| `setName(value)` | set intrinsic object/prototype name |
| `lock(value)` | prevent adding new keys when locked |
| `bracketAccess(value)` | enable or disable bracket string-key access |
| `get(key)` | direct map/object key read |
| `set(key, value)` | direct map/object key write |
| `has(key)` | key existence check |
| `delete(key)` | delete a key |
| `iterator()` | iterator helper |
| `next()` | iterator helper |
| `keys()` | list own keys |
| `values()` | list own values |

## Notes

Operator hooks apply to object instances, not plain maps used only as data. Class instances and constructed object values are the normal place to define these methods.

For arithmetic-style operators, Pilang tries left-side `compute` first and then right-side `rcompute` when the right operand is an object instance. For `equals` and `compare`, Pilang can try either side.

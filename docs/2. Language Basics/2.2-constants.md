# 2.2 Constants

Pilang supports constant bindings with `const`. A `const` binding must keep the
same binding after it is declared, so assigning a new value to that name is an
error.

```swift
const PI_APPROX = 3.14159;
const MAX_ITEMS = 100;

PI_APPROX = 3; // error
```

`const` is binding immutability, not deep value immutability. Mutable values
stored in a `const` binding can still be changed through indexing or fields.

```swift
const values = [1, 2, 3];
values[0] = 99; // ok

const config = {debug: false};
config.debug = true; // ok
```

## Literal Constants

These values are built into the language syntax:

```swift
true;
false;
nil;
INF;
NAN;
```

- `true` and `false` are boolean values.
- `nil` represents the absence of a value.
- `INF` represents infinity.
- `NAN` represents "not a number".

## Module Constants

Some built-in modules also provide constants. For example, math, system, OS, drawing, and language modules may define named values that should be treated as read-only API values.

```swift
import math;

println(math.PI);
println(math.E);
```

## Convention

Use `const` for names that should not be rebound. Uppercase names are still a
useful convention for module-level constants that are part of an API.

```swift
const DEFAULT_TIMEOUT = 30;
```

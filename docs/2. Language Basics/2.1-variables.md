# 2.1 Variables

Variables store values under a name. In Pilang, declare a mutable variable with
`let`.

```pilang
let name = "Pilang";
let count = 3;
let ready = true;
```

If a variable is declared without an initializer, its value is `nil`.

```pilang
let result;
println(result); // nil
```

You can declare more than one variable in the same `let` statement.

```pilang
let x = 10, y = 20;
let left = "a", right;
```

## Names

Variable names are identifiers. They may contain letters, digits, and underscores, but they cannot start with a digit.

```pilang
let total = 0;
let total_count = 4;
let _cache = [];
```

Reserved keywords such as `if`, `for`, `fun`, `class`, `true`, `false`, and `nil` cannot be used as variable names.

## Reassignment

Variables declared with `let` can be assigned new values.

```pilang
let score = 0;
score = score + 10;
score += 5;
```

Use `const` when the name should keep pointing at the same value.

```pilang
const max_items = 100;
max_items = 200; // error: cannot reassign a const binding
```

`const` protects the binding, not the value itself. If the value is mutable, its
contents can still change.

```pilang
const scores = [10, 20];
scores[0] = 99; // ok

const user = {name: "Ada"};
user.name = "Mira"; // ok
```

## Local Scope And Global Hoisting

Inside a local scope, use `let` or `const` when you want a new local binding. If
you assign to a new name without a declaration inside a local scope, Pilang
hoists that name to the module's global scope instead of creating a local
variable.

```pilang
fun configure() {
    let local_value = 10; // local to configure
    global_value = 20;   // hoisted to module/global scope
}

configure();
println(global_value); // 20
```

This is useful for deliberate module-level state, but it can also create
accidental globals. Prefer `let` or `const` for local bindings.

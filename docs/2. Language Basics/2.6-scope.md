# 2.6 Scope

Scope controls where a name can be used and which variable an assignment changes.
Pilang has module/global scope, local scopes, and captured outer scopes for
closures.

The most important rule is:

- at the top level, names belong to the current module
- inside a local scope, `let` creates a mutable local binding
- inside a local scope, `const` creates a local binding that cannot be rebound
- inside a local scope, assignment without a declaration writes an existing
  local when one is visible, otherwise it writes a module/global variable

## Module And Global Scope

Every `.pi` file is treated as a module. The top level of that file is the
module's global scope.

```swift
let greeting = "hello"

fun say_greeting() {
    println(greeting)
}
```

Here, `greeting` and `say_greeting` are module-global names. Functions declared
in the same module can read those names.

Top-level assignment also creates or updates module globals.

```swift
count = 0

fun next() {
    count = count + 1
    return count
}
```

Use `let` or `const` at the top level when you are declaring a name
intentionally. Plain assignment is accepted at the top level too, but an
explicit declaration makes the code clearer.

## Module Exports

Top-level public names are exported automatically. There is no separate
`export` statement in normal Pilang modules.

```swift
// math_tools.pi
let scale = 2

fun double(n) {
    return n * scale
}
```

Another module can import and read those exports:

```swift
import math_tools

println(math_tools.scale)
println(math_tools.double(10))
```

The module exports `scale` and `double` because both names are defined at the
top level.

Local names are not exported.

```swift
fun double(n) {
    let factor = 2
    return n * factor
}
```

`factor` exists only while `double` is running. Other modules cannot import
`factor`, and it does not appear as `math_tools.factor`.

## Private Module Names

A top-level name that starts with `_` is private to the module import system.
Code inside the same module can use it, but outside modules cannot import or
access it as a public export.

```swift
let visible = 42
let _hidden = 99

fun total() {
    return visible + _hidden
}
```

This module exports `visible` and `total`, but `_hidden` is private.

```swift
import tools

println(tools.visible)
println(tools.total())

// Invalid from outside the module:
// println(tools._hidden)
```

Private names are also skipped by wildcard imports.

```swift
import tools.*

println(visible)
// _hidden was not imported
```

The leading underscore rule applies to top-level module names. Object fields and
class members that start with `_` are only private by convention unless a
specific API says otherwise.

## Imports And Current Scope

An import creates a name in the importing module's scope.

```swift
import math

println(math.sqrt(25))
```

An alias changes the imported local/global name:

```swift
import math:m

println(m.sqrt(25))
```

Selected imports bind exported names directly in the current module:

```swift
import math.{floor, ceil}

println(floor(3.9))
println(ceil(3.1))
```

Wildcard imports also bind names in the current module/global scope:

```swift
import math.*

println(sqrt(25))
```

Because imports create names in the importing module, imported bindings can
conflict with names you already declared. Prefer aliases or selected imports in
larger files so the source of each name stays clear.

## Module State

Each loaded module has its own global storage. When a module is imported, its
top-level code runs once and its exports are cached by resolved module path.

```swift
// counter.pi
let count = 0

fun next() {
    count = count + 1
    return count
}
```

```swift
import counter

println(counter.next()) // 1
println(counter.next()) // 2
```

If another file imports the same `counter` module, it sees the same module
state. The module is not re-run for each import.

## The `module` Variable

Inside a module, `module` refers to the current module object.

Common fields are:

- `module.name`: the module name
- `module.path`: the resolved source path when available
- `module.is_main`: whether this file is the entry module
- `module.exports`: the map of public exports

```swift
println(module.name)
println(module.is_main)
println(module.exports)
```

The main file passed to the runner is also a module. Its top-level names are
module globals, and `module.is_main` is true for that entry file.

## Local Scope

Pilang creates local scopes for blocks, functions, loops, and comprehensions.
A local variable shadows an outer variable with the same name while that local
scope is active.

```swift
let name = "module"

if true {
    let name = "block"
    println(name) // block
}

println(name) // module
```

After the block ends, the block-local `name` is gone.

## Block Scope

A block is code enclosed in `{` and `}`. Bindings declared with `let` or `const`
inside a block are local to that block.

```swift
if ready {
    let message = "ready"
    println(message)
}

// message is not available here
```

Blocks can read names from outer scopes.

```swift
let status = "ready"

if status == "ready" {
    println(status)
}
```

Use `let` or `const` when you want a new block-local name. Without a
declaration, assignment writes an existing visible local if there is one, or a
module/global name otherwise.

```swift
let status = "idle"

if true {
    status = "ready" // updates the module-global status
}

println(status) // ready
```

## Function Scope

Function parameters are local variables. Bindings declared with `let` or `const`
inside a function are also local to that function.

```swift
fun add(left = 0, right = 0) {
    let result = left + right
    return result
}
```

`left`, `right`, and `result` are not available outside `add`.

Functions can read module globals:

```swift
let prefix = "user:"

fun label(name) {
    return prefix + name
}
```

Functions can also update module globals when assignment is not declaring a new
local:

```swift
let calls = 0

fun record_call() {
    calls = calls + 1
}
```

Be careful with assignment without a declaration inside functions. If no local
with that name exists, the assignment creates or updates a module/global name.

```swift
fun accidental_global() {
    total = 10
}

accidental_global()
println(total) // 10
```

To keep the value local to the function, use `let`:

```swift
fun local_total() {
    let total = 10
    return total
}
```

## `let` Declarations

`let` declares a new variable in the current scope.

```swift
let x = 1
let y
let a = 1, b = 2, c
```

At the top level, `let` declares module-global names. Inside a function or
block, `let` declares local names.

```swift
let value = "module"

fun demo() {
    let value = "local"
    println(value)
}

demo()          // local
println(value) // module
```

Assignment without a declaration is different: it changes an existing name if
one is visible, or creates/updates a module global when no local target exists.

```swift
let value = "module"

fun update() {
    value = "changed"
}

update()
println(value) // changed
```

Inside a local scope, use `let` for temporary values, loop helpers, and function
intermediate results. This avoids accidental module state.

## `const` Declarations

`const` follows the same scope rules as `let`, but the binding cannot be
reassigned.

```swift
const version = "1.0"

fun show() {
    const label = "version:"
    println(label + version)
}
```

The value behind a `const` binding can still be mutable.

```swift
const items = []
items.append("ready") // ok
items = []            // error
```

## Loop Scope

`for` loop variables are scoped to the loop body.

```swift
for i in 1..5 {
    println(i)
}

// i is not available here
```

Variables declared with `let` or `const` inside the loop body are local to that
loop body.

```swift
for item in [1, 2, 3] {
    let doubled = item * 2
    println(doubled)
}
```

If a loop needs to update an outer variable, declare that outer variable before
the loop and assign to it inside the loop.

```swift
let total = 0

for item in [1, 2, 3] {
    total = total + item
}

println(total) // 6
```

## Comprehension Scope

Comprehension variables are local to the comprehension expression.

```swift
let values = [x * 2 : x in 1..3]

// x is not available here
```

Comprehensions can read outer names:

```swift
let factor = 10
let values = [x * factor : x in 1..3]
```

## Shadowing

Shadowing means declaring a local name with the same name as an outer variable.
The local name is used inside the local scope.

```swift
let mode = "prod"

fun test_mode() {
    let mode = "test"
    println(mode) // test
}

test_mode()
println(mode) // prod
```

Shadowing is useful for short-lived local meanings, but avoid it when it makes
the code hard to read.

## Closures

Nested functions can capture variables from outer scopes.

```swift
fun make_counter() {
    let i = 0

    fun count() {
        i = i + 1
        return i
    }

    return count
}
```

The inner `count` function keeps access to `i` after `make_counter` returns.
Captured variables are shared with the closure, so assigning to `i` inside
`count` updates the same captured variable.

```swift
let counter = make_counter()

println(counter()) // 1
println(counter()) // 2
```

Each call that creates a closure gets its own captured locals.

```swift
let a = make_counter()
let b = make_counter()

println(a()) // 1
println(a()) // 2
println(b()) // 1
```

## Practical Rules

- Use `let` for new mutable variables.
- Use `const` for names that should not be rebound.
- Put reusable module state at the top level.
- Prefix top-level helper names with `_` when they should stay private.
- Use assignment without a declaration only when you mean to update an existing
  value.
- Prefer local variables inside functions to avoid accidental module globals.
- Prefer import aliases or selected imports when many modules are involved.
